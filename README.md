# Star Battle Hints · 星战谜题提示工具

> **先教思路，再给一步；结论必须可验证。**
>
> Supports NxN Star Battle / 星之战，`k` 星/行、列、区域，含经典 1★、2★ 和 17×17 4★ 等。仅分析静态棋盘，无需账号或联网。

## 项目用途

这套工具用于**反复向 ChatGPT 请求逻辑提示、检查错误标记，而不是直接公布答案**。

- **`hint`**：每次最多给一个可证明的步骤（默认优先人类易理解的局部规律），也可只告诉你该看哪个区域。
- **`check`**：验证当前标记是否与规则相容。只有**空盘唯一解已经得到证明**时，才会把与该解不同的星/叉逐个判定为错误；多解时只报告可以单独证明不可能的标记。
- **`solve --reveal`**：显示完整解，必须显式选择，防止误剧透。
- **`tools/grid_overlay.py`**：给截图叠加 1-based 行列编号，减少读错区域的概率；*它不会识别图片或自动转录区域*。

### 规则建模

`N×N` 个二元变量，`x[r,c]∈{0,1}`。满足：

1. 每行恰有 `k` 颗星。
2. 每列恰有 `k` 颗星。
3. 每个由粗线围成的区域恰有 `k` 颗星；区域总数应为 `N`。
4. 每个 `2×2` 小方块的星数 `≤1`。这与**两颗星不可上下左右或斜向接触**等价。
5. 已标星星强制为 1，红叉强制为 0。蓝色/其他高亮是玩家记号，不自动当作星星。

底层使用 SciPy/HiGHS 的**混合整数线性规划（MILP）**进行精确可满足性检查；对被检验的位置附加相反假设求解。`unsat` 才是已证反证成立，**求解超时 (`unknown`) 绝不能当作无解**。

## 快速开始

要求 Python 3.11+。推荐 `uv`（或 `pip`）：

```bash
# 仓库目录中
uv sync
uv run starbattle examples/6x6-1star-demo.json hint --level 1
uv run starbattle examples/6x6-1star-demo.json hint --level 2
uv run starbattle examples/6x6-1star-demo.json hint --level 3
uv run starbattle examples/6x6-1star-demo.json check
uv run starbattle examples/6x6-1star-demo.json solve --reveal
```

没有 uv 也可以：

```bash
python -m pip install -e .
python -m starbattle examples/6x6-1star-demo.json hint
python -m unittest discover -s tests -v
```

提示通过结构化 JSON 返回：

```json
{
  "type": "star",
  "cell": [3, 5],
  "level": 2,
  "scope": "区域 A",
  "reason": "示意：这个格子在所有局部合法摆法中都出现。",
  "warnings": []
}
```

**注意：这段输出只是字段示意，不是示例题实际计算结果。** 坐标统一是 `[行, 列]`、**从 1 开始**。

## 如何录入新棋盘

编辑 JSON：

```json
{
  "size": 6,
  "stars_per_unit": 1,
  "regions": [
    "AAAAAA",
    "BBBBBB",
    "CCCCCC",
    "DDDDDD",
    "EEEEEE",
    "FFFFFF"
  ],
  "stars": [[1, 1]],
  "crosses": [[1, 2], [2, 1], [2, 2]]
}
```

`regions` 每个字符表示该格所属区域，与字母本身含义无关。相同字符的格子属于同一个黑线区域；必须恰好有 `N` 种区域标签。也支持每行写成字符串标签数组（如 `["top-left", "top-left", ...]`），避免尺寸很大时单字符不够。

**转录截图的可靠流程：**

1. 确认截图中实际 `N` 与 `k`，明确左上角为 `R1C1`，行优先、列其次。
2. 给截图编号；可选 `grid_overlay.py` 生成参考图。放大看**粗黑边界**，为格子填区域标签，切忌通过格子颜色猜区域。
3. 录入已有星星到 `stars`、红叉到 `crosses`；**蓝色高亮只当备注**，除非用户明确它是已放星或禁放。
4. 先核对区域总数、连接性警告、星星/红叉坐标，再运行 `check` 与 `hint`。
5. 若题本身读错（错误的区域线或行列坐标），任何数学求解器都会给出**针对错误转录的正确计算**；不要自信地引用其结论。

截图叠加坐标的例子（需安装 `uv sync --extra image` 或 `pip install Pillow`）：

```bash
python tools/grid_overlay.py board.png --rect 6 502 679 1139 --size 17 -o overlay.png
```

`--rect` 四个数字必须是**该张图片**外框 `left top right bottom` 的实际像素，示例数字不可通用。

## 提示等级

| 等级 | 输出 | 目的 |
|---|---|---|
| `--level 1` | 只说该看哪行/列/区域，不给坐标 | 最少剧透，练习观察 |
| `--level 2`（默认） | 给**一格**的星或叉，加局部证据 | 平衡解题感与学习 |
| `--level 3` | 允许全局反证（假设某格相反会导致无解） | 用于卡关，保证是强制结论 |

**局部优先顺序：**

1. **已满单元**：该行、列或区域已放满 `k` 星 → 其余全是叉。
2. **剩余容量**：某单元还差 `m` 星、只剩 `m` 个可选格 → 它们都是星。
3. **不相邻**：已有星的 8 邻域 → 禁放。
4. **单位内组合/打包**：枚举行、列或区域内的合法 `k` 星组合（与已有星不接触）。如果某格存在于**全部**局部合法组合 → 星；如果存在于**零个**组合 → 叉。
5. **全局反证**（第 3 级）：把某候选星格暂时禁掉，若整盘不可满足 → 必放星；对候选空格反之亦然。

局部组合故意**放宽**其他行列/区域要求，所推出的必然结论因此依旧可靠，但不一定完整。组合超过安全上限时跳过，不会依据不完整枚举断言必然。

### 练习用人类推理模版

优先建议 ChatGPT：

- **分组计数 / Pigeonhole**：整行、跨行带状区、相邻两列合计星数，对应区域的可容纳最大数量。
- **区域内打包**：细长区域的相邻位置互斥；某些区段最多只能放一颗。
- **候选位置锁定**：若 `k` 颗星被锁在某几行/列，则它们占掉对应行/列配额。
- **反证法**：假设某个候选是星（或不是星），逐步找到某行/列/区域星数无法满足的矛盾。

以上是**教学提示方法**，并非每一种都已被自动化为可读的链式证明；脚本第 3 级只提供全局反证可满足性结论，不会凭空编造简短人工证明。

## 排错时要特别保守

`check` 的关键是**区分三种情况**：

- 原题无解：很可能区域转录错了，先核对截图。
- 原题唯一解：当前星星不在唯一解里 → 必错；当前红叉挡住唯一解星格 → 必错。
- 原题多解：当前无解可能是多个标记联合冲突；某个标记与**任选的一个解不同并不代表它错了**。只有单独作反证确立不可能，才判定为错。

即使确认了若干错误格，也**不能从结果逆推出哪个动作在时间上最先填错**；必须有历史操作记录才能追溯。

## 对 ChatGPT 的固定提问规范

参阅 [CHATGPT_PROMPT.md](CHATGPT_PROMPT.md)。下次直接附最新截图，并说“按 star-battle-hints 的 1 级/2 级给提示”或“帮我 check”。对于新截图，先确认区域转录，尤其是粗黑线、坐标与蓝色记号含义。

## 示例与测试

- `examples/6x6-1star-demo.json`：简化验证用题，**不保证唯一解**；区域刻意设成水平条，便于自动测试。
- `examples/17x17-4star-blank-template.json`：仅格式参考，**不是 2026-11-04 的真实谜题**。需要完全替换区域布局。

## 局限与路线图

当前版本不提供**自动从截图识别**格子或粗黑区域，不输出人类可逐句复核的全局反证链，也不识别历史操作顺序。后续可以增加半自动图像格线转录与确认界面、更多集合式逻辑（Hall set / fish）、不可满足核心解释、交互式提示和真实谜题回归测试。

## 实验性截图半自动转录

如果是与示例类似的**浅色背景、深色粗线、黑色星形和红叉**风格，可以试用：

```bash
uv sync --extra image
uv run python tools/transcribe_screenshot.py screenshot.jpg \
  --rect LEFT TOP RIGHT BOTTOM --size 17 --stars-per-unit 4 \
  -o current-board.json
uv run starbattle current-board.json check
```

它通过边界粗细的像素阈值和格子中心颜色进行检测，**不是通用 OCR / 万能识图器**：放大缩小、深色主题、抗锯齿、棋盘偏移都可能导致误识别。即使程序恰好识别到 17 个区域，也不等于标签百分之百正确；请逐项核对。识别失败时优先人工确认而不是修改规则凑答案。`--boundary-threshold` 可以微调粗黑线阈值。

2026-11-04 用户提供的 17×17、4★ 截图已生成结构化回归数据 `examples/2026-11-04-17x17-4star-transcribed.json`（仅保留棋盘数据，不附游戏截图）。此例求解器证明原题唯一解，并发现 4 个不可能的星标记和 3 个错误红叉；`tests/test_star_battle.py` 会反复验证这个结果。
